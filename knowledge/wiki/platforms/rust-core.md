**Verified Fact.** Classic 的 Worker 已使用 `ClassicStaticContext` 與 `ClassicPoseSnapshot` 切分資料。Hybrid 主端用 `createHybridGeometryCompiler` 保留編譯的有限面片與 BVH，Worker 收 `HybridStaticGeometry`，接下來依靜態 fingerprint 與 pose snapshot 算 direct、first-order、bounded second-order。Hybrid 的 audible Portal route 與 reflection tap projection 由 viewport adapter 呼叫額外的 TS 計算，Worker 的 `HybridDirectFrame` 與 Classic 的 `AcousticFrame` 具有不同形狀。只測 Hybrid Worker 的 direct 部分會漏計後續 Portal 與 UI 端工作。 [Classic compute](../../../src/acoustics/compute-frame.ts) · [Hybrid compile](../../../src/acoustics/hybrid3d/compile.ts) · [Hybrid Worker](../../../src/workers/hybrid-direct.worker.ts) · [Hybrid adapter](../../../src/components/workspace/HybridViewportAdapter.tsx)

## 移植順序與最小工作切片

| 順序 | TS 基準與原型工作 | 相容性風險與驗證 |
| --- | --- | --- |
| 0 · 凍結行為 | 從現行 serial 函式擷取有版本的 Classic/Hybrid fixtures。記錄輸入、預期排序、實際環境與 field-specific tolerance | 基準先通過現行 Vitest，固定時間戳，保留失敗案例與原始輸出 |
| 1 · 純幾何 | 移植 [Classic 2D geometry](../../../src/acoustics/geometry.ts) 的 segment/collinear rules 與 [Hybrid 3D geometry](../../../src/acoustics/hybrid3d/geometry.ts) 的 vector、AABB、finite-patch segment/ray | 保留 `1e-8` 判斷、端點排除、平行、共線、patch 邊界與 Portal opening 例外。spatial schema 的 `1e-6 m` 是另一層驗證，沿用各自邊界 |
| 2 · BVH、直達路徑 | 先餵 TS 編譯的面片讓 Rust 建 [BVH](../../../src/acoustics/hybrid3d/bvh.ts)，移植 build、segment/ray traversal、any-hit，然後 [Hybrid direct](../../../src/acoustics/hybrid3d/direct.ts) 和 Classic 的 direct occlusion | 固定 longest-axis/tie rules、hits 排序、occluder 去重、可見性、距離與方位。Any-hit 只替換 boolean 查詢。完整 hit 診斷保留 sorted all-hits |
| 3 · 早期反射 | 先移植 [Classic image-source](../../../src/acoustics/image-source.ts) 與 [Hybrid first-order](../../../src/acoustics/hybrid3d/reflections.ts) 的單路徑幾何與反射 leg visibility。再做 [Hybrid bounded second-order](../../../src/acoustics/hybrid3d/second-order.ts) 與 Classic blocked-only search | 鎖定 physical surface IDs、順序、代表面片、候選上限、遮擋判斷及六個共用 audible taps。用小型 exhaustive reference 輔助診斷候選差異，產品等價以現行 pruned solver 為準 |
| 4 · 傳播與 frame | [Classic Portal graph](../../../src/acoustics/portal.ts)、[Hybrid audible routing](../../../src/acoustics/hybrid3d/audible-direct.ts)、[Tap projection](../../../src/acoustics/hybrid3d/reflection-rendering.ts)、[Material registry](../../../src/domain/materials/registry.ts)、[三頻 Eyring](../../../src/acoustics/room-acoustics.ts)、source shard/frame assembly。最後再比較 Rust finite patch compile 與 [primitives](../../../src/acoustics/hybrid3d/primitives.ts) | 保留 Portal tie/cost、完整 route points、3D 段可見性、三頻係數、gain/loss/cutoff 與夾限。避免在同一 PR 改演算法和 backend。未移植的 TS 階段分開計時與標示 |

**Proposed Design.** 先做 Hybrid 的 finite segment/BVH/direct + first-order，因這條可獨立和現行 serial fixtures 及 Worker 輸出比較。Classic 2D segment 語意同步納入純函式基準，兩者共享單位與共同工具，分別保有自己的幾何型別與路徑分類。 `echo-acoustics-core` 輸出 library，公開純型別及 `compile_static`、`solve_shard`、`assemble` 等同步試作介面。核心沒有 React、Next、Tauri、Web Audio、CPAL、檔案 I/O、時鐘或 OS thread API 依賴。材料表在 prototype 從 TS registry 生成版本化資料，校驗 checksum、ID、三頻欄位和 `absorption + transmission + reflection` 相關現行不變量；資料來源改成共同表格另行審查。Wrapper 提供 timestamp、驗證外部 DTO、cache/transport、error mapping 與 scheduler。P5 receiver、P6 六頻／大氣、P7 directional histogram 保留資料型研究定位。 [現行聲學規格](../../../docs/ACOUSTICS.md) · [平台來源 P10、P11](../../raw/references/platforms.md)

### 相容性門檻

- **座標及數值。** Classic 的 planar `{x,y}` 對應 Hybrid `{x, elevation, z=y}`，`y` 高度按現行 floor elevation 轉換，距離用 m、角度用 deg、delay/pre-delay 用 ms、RT60 用 s、gain/loss 用 dB、cutoff 用 Hz，聲速維持 343 m/s。第一版使用 `f64`，避免自行改比較順序、改為 fast math、顯式 FMA 或 `f32`。浮點運算／`hypot`／`atan2`／`log` 跨 runtime 逐欄位驗證。以既有 assertions 定初始門檻，只有未覆蓋欄位才先提獨立誤差預算，凍結後再跑 Rust 結果。 [Classic geometry](../../../src/acoustics/geometry.ts) · [Hybrid geometry](../../../src/acoustics/hybrid3d/geometry.ts) · [基準與數值驗證](../performance/benchmark-plan.md)
- **精確欄位。** Visibility、route kind、source/surface/path IDs、離散 hit 與 reflection 排序、tap 數、指派／版本／fingerprint 必須精確。特別對 equal score、近臨界門檻、大小寫、數字、連字號及底線的 ID 建 fixture。現行 tie-breaker 使用 JS `localeCompare`；Rust 字節排序並非同語意。先以 TS oracle 生成帶 locale／ICU 資訊的 rank fixtures，移植未達成一致前把 ordering 留在 TS adapter，或者由 TS 提供與現行語意一致的 rank table。若同一 fixture 跨平台發現現行差異，開 ADR 決定固定排序與影響範圍。 [Classic reflections](../../../src/acoustics/image-source.ts) · [Hybrid reflections](../../../src/acoustics/hybrid3d/reflections.ts) · [平台來源 P19](../../raw/references/platforms.md)
- **三種 fingerprint。** `createClassicStaticContext` 對 static scene 的 JSON 運算 FNV-1a。Hybrid `hybridStaticGeometryHash` 對幾何子集運算，geometry identity 與 downstream 材料／路由輸入仍須按現行責任分開。 `classicProjectionHash` 是 `SceneDocumentV2` 的獨立相容欄位，由 stable JSON 計算。第一版保留 TS 產生這三者，Rust 以 opaque token 回傳。移植 fingerprint 前需 golden canonical bytes，測 key ordering、`null`／省略值、`-0`、decimal/exponent、Unicode BMP/astral 字元和 JS 字串迭代規則。32-bit fingerprint 與任何來自 UI 的值都不能作為授權或唯一 identity，須搭配 session/generation/驗證過的靜態 payload。 [Classic static](../../../src/acoustics/compute-frame.ts) · [Hybrid static](../../../src/acoustics/hybrid3d/compile.ts) · [SceneDocumentV2 驗證](../../../src/domain/scene-document/validate.ts)
- **邊界與錯誤。** 保留 SceneSpec v1、SceneDocumentV2、Workspace transfer/cache migration、既有 bounds、有限數值、禁用實體投影、ID 約束及一個 active listener。Serde decode 後重做必要語意驗證，對 bytes、數量、面片展開、累計工作量、溢位、重複／未知 ID、非法零向量及 non-finite 結果有限制。測 malformed/oversize、相切／共面、空障礙、門縫、直達→遮蔽切換、Portal 後段阻擋和 coincident poses。時間戳與異步排程只在 wrapper 記錄。 [Workspace 投影](../../../src/domain/workspace/projections.ts) · [API contracts](../../../docs/API_CONTRACTS.md)

## Runtime wire contract 提案

| 操作 | 欄位、所有權與失敗策略 |
| --- | --- |
| `INSTALL_STATIC` | envelope 含 `protocolVersion`、mode、workspace session/epoch、request ID、TS canonical fingerprint 與 bounded static projection。原型可傳有限面片給 Rust 建 BVH，後續再比較 native compile。驗證成功後原子安裝 immutable geometry，`STATIC_INSTALLED` 回 `staticHandle`、generation、request ID 與 fingerprint。舊 install 的遲到 ACK 無法換掉新 generation |
| `COMPUTE_SHARD` / `compute_pose` | 含 handle/generation、request sequence、revision、static fingerprint、mode、listener/source pose 與有序 ID／shard assignment，Hybrid 額外保留該請求的 projection hash。Classic snapshot 仍須帶現行 source 計算所需值。Web 首版以原 Worker 拆 shard，Desktop 可只送一個 pose job，由原生池拆分 |
| `FRAME` / error | Shard 輸出驗證 request、mode、revision、fingerprint、generation、projection hash、source 數量／順序和 finite 值後組完整 frame。Native 若已在 Rust 組裝，前端仍在 publish 前檢查整個 frame。錯誤回傳有限 code，保留狀態與 trace；不得混用兩種 backend 的 shard。先回退到最新可運算快照的同模式 TS serial |
| cancel / dispose | mode switch、project close、Worker restart、backend switch 或逾時會使 epoch/sequence 失效。以 cooperative cancel 減少浪費，逾時不能阻塞 UI；已送出的晚回覆丟棄。native immutable handles 在 in-flight job 退出後回收，失效、未知或跨 workspace handle 回可恢復錯誤 |

**Verified Fact.** 目前 Worker 以 `INSTALL_STATIC` ACK 和 `COMPUTE_SHARD` 驗證指派，pool coalesces pending scene，視情況接收同靜態結構、同 source 順序的 pose-lagging 完整 frame。Hybrid lagging frame 的到達方向標籤會等 current frame，overlay/audio 仍有連續性。此計畫保留現有的接受和呈現判斷。新 epoch/sequence 處理 undo/redo 可能重用 scene revision、backend restart 與不同 project 的隔離。結構變更使舊 generation 失效，後端崩潰或數值失敗採同模式完整 fallback。 [Classic Worker](../../../src/workers/classic-source.worker.ts) · [Hybrid pool](../../../src/workers/hybrid-direct-pool.ts) · [Frame acceptance](../../../src/acoustics/frame-acceptance.ts) · [ADR 0008](../../../docs/adr/0008-adopt-pose-lagging-frames.md) · [Hybrid 到達標籤](../../../src/components/workspace/HybridViewportAdapter.tsx)

### 交換成本與平台變體

1. **可讀 baseline。** Browser Worker 用 structured clone 結構 DTO，WASM wrapper 以相容的 `wasm-bindgen` crate／CLI 建 glue，對照 `serde-wasm-bindgen` 與少量 typed arguments。可選 `wasm-pack` 固定版本打包 JS/WASM 資產，production build 驗證 module worker URL 和 MIME。 [平台來源 P12、P13](../../raw/references/platforms.md)Desktop 先採 Tauri Commands JSON/Serde，低頻 control 與 pull frame 測完再決定是否用 Channel 做有序的完成通知。資料量由上限和最新待執行 pose 控制，Channel 的順序仍不能取代 frame freshness guard。TS 保有用於互動展示的原始 authoring geometry。Rust 常駐靜態 BVH、材料、面片索引與工作暫存，UI 取用完整 frame 所需點、ID、增益、filter、RT60／delay 與簡潔 diagnostics。 [平台來源 P03、P04、P14、P15](../../raw/references/platforms.md)
2. **可量測 reduced-copy。** 若 encode/decode 或 payload bytes 支配 tail latency，才比較 transferable ArrayBuffer、Tauri raw binary body/response 和 f64/u32 分段 typed arrays。明定 little-endian、version、offset/length/count/stride 上限、index bounds 及字串 table，禁止把 Rust struct 原始 padding 當 wire format。Transferred ArrayBuffer 的 sender view 失效，ownership 經回傳後才可重用。WASM memory grow／buffer replacement 之後重取 views，slice 所有權與 lifetime 明確，不跨 async 保留可失效的 view。測 clone/transfer 和 JS↔WASM／WebView IPC 的每一段 bytes、耗時、分配與 peak memory，raw 路徑仍可能複製。 [平台來源 P03、P15、P16](../../raw/references/platforms.md)
3. **可選平行。** 先做單執行緒 WASM，放在專屬 Worker，重用有上限的 Worker policy；每個 instance 會有自己的靜態記憶體。Native serial 為對照，Rayon 用本地固定池對 sources 或候選批次平行，輸出固定順序、閾值與 reduction order，預留 UI/音訊核心。四個 source 以下的小場景先比較 serial dispatch overhead。WASM SIMD 和 wasm-bindgen-rayon 都是獨立實驗，各需 runtime feature detection、配對 benchmark 與 fallback。Shared-memory threads 另需 COOP/COEP 與 `crossOriginIsolated`，驗證 embeds/assets／部署配置。常規 Web 部署目前不以 cross-origin isolation 作前置條件，禁用 nested pools。 [平台來源 P11、P13、P16、P17、P18](../../raw/references/platforms.md)

## 量測與採用

**Hypothesis.** 大型 Hybrid 場景在重複穿越與反射候選上可能受益於 Rust memory layout、無 GC 與 native 平行。小場景可能因 JS/WASM marshaling、靜態重複安裝或 native IPC 讓 p95 變差。先以 Criterion 測 native 內部函式，記錄冷/熱、編譯器、profile、target/CPU features、fixture digest、threads、OS、WebView/browser。整體選型以同機相同輸入的 end-to-end p50/p95/p99、主線程佔用、記憶體、遺漏／取消率與播放連續性為準，分開量 cold init、static install、shard compute、assembly 與 publish。若 parity、既有 stress gate、native audio continuity 或需求對應的實際預算未達標，保留 TS 路徑並把差距回記 benchmark evidence。 [基準與數值驗證](../performance/benchmark-plan.md) · [平台來源 P10、P20](../../raw/references/platforms.md)
